# Requirements: STC NanaST Execution Boundary

## Status

Sirius Wu approved this feature on 2026-09-09. It replaces the AMD64-only
`rfopt::host` boundary used by the first Boolean pass-through gate.

## Objective

NanaST must load its generated Forth source, invoke `nana-init` and
`nana-scan`, and access named `VARIABLE` cells through safe opaque handles on
AMD64 Linux and AArch64 Linux. The boundary must compile each definition as
native Subroutine-Threaded Code (STC).

## Public Boundary

rfopt exposes the boundary as `rfopt::nanast`.

- `Runtime::load` accepts one complete restricted source string.
- `Runtime::resolve_word` returns an opaque `WordHandle` for a colon
  definition.
- `Runtime::resolve_cell` returns an opaque `CellHandle` for a `VARIABLE`.
- `WordHandle::invoke` executes a validated zero-stack-effect lifecycle word.
- `CellHandle::read` and `CellHandle::write` access one cell without exposing
  its address.

The public error and handle-invalidity behavior remains compatible with the
retired boundary. A runtime accepts one successful load. A failed load leaves
it empty and allows a later retry.

## Source Contract

The boundary accepts only the generated top-level forms `VARIABLE` and colon
definitions. Definitions may use the NanaST Forth inventory defined in
[the code-generation requirements](../forth-codegen/requirements.md): literals,
cell addresses, `@`, `!`, arithmetic, comparisons, `AND`, `OR`, `0=`, and
nested `IF` / `ELSE` / `THEN` control flow.

Each definition must leave an empty Forth stack. The loader rejects unknown
words, unsupported literals, duplicate or reserved names, unbalanced control
flow, type-invalid stack effects, and definitions that exceed the configured
control or data-stack limits. Errors include source location where applicable.

A dynamic division by zero, or `isize::MIN / -1`, completes the native word
with an architecture-independent placeholder result (`0` or `isize::MIN`) and
returns a named execution error to the caller. The boundary does not roll back
any cell writes that preceded the error.

## Platform Contract

- **AMD64 Linux:** The boundary lowers source through `X64Emitter` and runs it
  with the established STC register convention.
- **AArch64 Linux:** The boundary lowers the same source through `A64Emitter`
  and runs it with the established AAPCS64 STC convention.
- **Other platforms:** The `nanast` module is unavailable. This feature does
  not add ARM32 support.

## Acceptance Evidence

1. The NanaST integration gate runs the Boolean pass-through, state/reset, and
   arithmetic/comparison scenarios through `rfopt::nanast`.
2. rfopt unit tests cover source validation, atomic load behavior, handle
   lifetime, cell sharing, arithmetic, comparisons, and W^X executable memory.
3. The native AMD64 evidence runner executes the rfopt test suite and the
   NanaST integration gate on an `x86_64` Linux host.
4. GitHub Actions runs that runner on `ubuntu-24.04` for pull requests and
   changes to `main`. The `RFOPT_SUBMODULE_TOKEN` repository secret provides
   read access to the private pinned submodule. The runner rejects every host
   that is not Linux AMD64.
5. The AArch64 execution gate runs the same `nanast` unit tests on AArch64
   hardware or an AArch64 emulator with a Linux userspace. The native Linux
   evidence is recorded in
   [AArch64 verification](../../verification/stc-nanast-boundary/aarch64.md).
6. `scripts/run-rfopt-target.sh` permits AMD64 and AArch64 Linux hosts while it
   continues to require a clean, pinned rfopt submodule.

## Boundaries

- Do not expose raw Forth cell addresses, dictionary entries, or code pointers.
- Do not route this boundary through terminal I/O, a CLI, or BNC hardware.
- Do not make real-time latency or safety claims from this host-side boundary.
- Do not retain the AMD64 machine-stack emitter after the STC boundary passes
  the required gates.
